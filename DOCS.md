# coffee-templater для Go: документация

Подробное руководство на русском. Краткий обзор на английском лежит в [README.md](README.md), справочник
по API в godoc: `go doc -all github.com/vitJR1/coffee-templater.go`.

Всю работу с документами выполняет ядро
[coffee-templater-engine](https://github.com/vitJR1/coffee-templater-engine) (Rust → WebAssembly).
Оно встроено в модуль, отдельно ставить ничего не нужно. Эта библиотека — Go-обёртка над ним.
То же ядро работает в [coffee-templater.js](https://github.com/vitJR1/coffee-templater.js), поэтому
документ, отрендеренный из Go, побайтово совпадает с документом из Node.js.

## 1. Установка и требования

```bash
go get github.com/vitJR1/coffee-templater.go
```

```go
import coffee "github.com/vitJR1/coffee-templater.go"
```

- Go 1.23 или новее.
- **Без cgo.** Ядро — файл `coffee_core.wasm` (около 1 МБ), встроенный через `go:embed`. Его
  исполняет [wazero](https://wazero.io), рантайм WebAssembly на чистом Go. Бинарник собирается обычным
  `go build` под любую платформу, в том числе `CGO_ENABLED=0` и кросс-компиляцией.
- На amd64 и arm64 ядро компилируется в машинный код. На остальных архитектурах wazero выполняет его
  интерпретатором: работает, но медленнее.
- На вход принимается `[]byte`, на выходе всегда `[]byte`.

## 2. Быстрый старт

```go
package main

import (
	"context"
	"log"
	"os"

	coffee "github.com/vitJR1/coffee-templater.go"
)

func main() {
	ctx := context.Background()
	templater := coffee.New(coffee.Options{})

	template, err := os.ReadFile("invoice.docx")
	if err != nil {
		log.Fatal(err)
	}
	doc, err := templater.Render(ctx, template, map[string]any{
		"number": 42,
		"client": map[string]any{"name": "Иван Петров"},
		"items": []map[string]any{
			{"name": "Кофе", "qty": 2, "price": 10.5},
			{"name": "Чай", "qty": 1, "price": 4},
		},
		"paid": false,
	})
	if err != nil {
		log.Fatal(err)
	}
	if err := os.WriteFile("invoice-42.docx", doc, 0o644); err != nil {
		log.Fatal(err)
	}
}
```

Тот же вызов работает для `.xlsx` и `.pptx`: формат определяется по содержимому файла.

### Скомпилировать один раз, рендерить много раз

`Templater.Render` каждый раз заново разбирает шаблон. Если шаблон рендерится многократно, скомпилируйте
его один раз:

```go
tpl, err := templater.Compile(ctx, template)
if err != nil {
	return err // все ошибки шаблона сразу, см. раздел 13
}
defer tpl.Close()

for _, inv := range invoices {
	doc, err := tpl.Render(ctx, inv)
	// …
}
```

`*Templater` и `*Template` безопасны для одновременного использования из многих горутин.

## 3. Синтаксис шаблонов

Теги пишутся прямо в тексте документа в Word, Excel или PowerPoint. Разделители по умолчанию —
`{{` и `}}`, их можно поменять (раздел 11).

### Переменные

| Тег | Что выводит |
| --- | --- |
| `{{name}}` | поле `name` |
| `{{client.address.city}}` | вложенное поле |
| `{{items[0].name}}`, `{{items[-1].name}}` | элемент массива по индексу, отрицательный — с конца |
| `{{map["ключ с пробелами"]}}` | поле с произвольным именем |
| `{{list.length}}` | длина массива или строки |
| `{{имя_клиента}}` | кириллица в именах допустима |

Имена полей — это ключи JSON, то есть для структур имена из тегов `json` (раздел 10).

Значения выводятся так:

| Значение | Результат |
| --- | --- |
| строка | как есть (XML-символы экранируются автоматически) |
| число | как записано: `json.Number("1.50")` даст `1.50`, `10.5` даст `10.5` |
| `bool` | `true` / `false` |
| дата | ISO-строка, либо в формате `Options.DateFormat`; для своего формата есть фильтр `date` |
| массив | элементы через `, ` |
| объект | JSON |
| `nil` / отсутствующее поле | по `Options.NullValue`, по умолчанию пустая строка |

Перевод строки `\n` в значении становится настоящим переносом строки в документе, `\t` — табуляцией
(в Word). Отключается опцией `NoLinebreaks: true`.

### Секции

| Тег | Назначение |
| --- | --- |
| `{{#items}}…{{/items}}` | массив — цикл; объект — смена контекста; иначе — условие по истинности |
| `{{#each items}}…{{/each}}` | явный цикл; для объектов перебирает значения, ключ — в `{{@key}}` |
| `{{#if paid}}…{{/if}}` | условие |
| `{{#unless paid}}…{{/unless}}` | условие «если нет» |
| `{{^items}}…{{/items}}` | инвертированная секция: рендерится, если значение пустое или ложное |
| `{{else}}` | ветка «иначе» в любой секции |
| `{{/}}` | закрывает ближайшую открытую секцию |

Секция с фильтрами закрывается по пути: `{{#items | sort: "name"}}…{{/items}}`.

Истинность считается по правилам JavaScript: ложны `0`, `""`, `nil`, `false` и пустой массив, всё
остальное истинно (строка `"0"` тоже).

### Внутри цикла

| Выражение | Значение |
| --- | --- |
| `{{.}}` или `{{this}}` | текущий элемент |
| `{{name}}` | поле текущего элемента; если его нет, ищется во внешних областях |
| `{{../title}}` | значение из родительской области (`../../x` — на два уровня выше) |
| `{{@index}}` | номер элемента с нуля |
| `{{@number}}` | номер элемента с единицы |
| `{{@first}}`, `{{@last}}` | первый / последний элемент |
| `{{@length}}` | длина перебираемого массива |
| `{{@key}}` | ключ (в `#each` по объекту) |

Пример — список через запятую с точкой в конце:

```
{{#items}}{{name}}{{#@last}}.{{/@last}}{{^@last}}, {{/@last}}{{/items}}
```

### Строковые литералы

Аргументы фильтров можно писать в любых кавычках: `"…"`, `'…'`, а также в типографских `“…”`,
`«…»`, `‘…’`, которые Word подставляет автоматически при наборе. Числа: `42`, `-1.5`.
Ключевые слова: `true`, `false`, `null`.

## 4. Циклы: что именно повторяется

Главный вопрос любого Office-шаблонизатора — что дублировать: текст, абзац или строку таблицы.
Здесь это решается **по положению открывающего и закрывающего тегов**:

| Где стоят теги | Что повторяется |
| --- | --- |
| в одном абзаце (или одной ячейке Excel) | текст между тегами |
| каждый тег один в своём абзаце | абзацы между ними; сами абзацы с тегами удаляются |
| в разных ячейках одной строки таблицы (Word, PowerPoint) | вся строка таблицы |
| в разных ячейках одной строки листа (Excel) | вся строка листа |
| в разных строках таблицы или листа | диапазон строк от первой до последней |

Другие сочетания, например секция, которая начинается в абзаце, а заканчивается внутри таблицы, дают
ошибку `invalid_section`.

### Повтор текста внутри абзаца

```
Теги: {{#tags}}[{{.}}] {{/tags}}
```
→ `Теги: [кофе] [чай]`

### Повтор абзацев

```
Позиции:
{{#items}}
• {{name}} — {{price | number: 2}} ₽
{{/items}}
Итого: {{total}}
```

Абзацы `{{#items}}` и `{{/items}}` из результата исчезают, между ними может быть сколько угодно
абзацев, таблиц и картинок. Чтобы сработал этот режим, в абзаце с тегом не должно быть ничего,
кроме тега и пробелов.

### Повтор строк таблицы (Word, PowerPoint)

| Наименование | Кол-во | Цена |
| --- | --- | --- |
| `{{#items}}{{name}}` | `{{qty}}` | `{{price}}{{/items}}` |

### Повтор нескольких строк

Если открывающий тег стоит в одной строке таблицы, а закрывающий в другой, повторяется
весь блок строк. Удобно для «карточек» из двух строк.

### Вложенность

Секции вкладываются друг в друга произвольно: строки таблицы внутри цикла по абзацам, условие
внутри строки таблицы и т.д. Пересекаться секции не могут, это ошибка `invalid_section`.
Глубина вложенности — до 48 уровней.

### `else` в циклах по абзацам и строкам

`{{else}}` должен стоять на том же уровне, что и теги секции: внутри абзаца, один в своём абзаце или
один в своей строке. В секции, повторяющей одну строку таблицы, `else` не поддерживается: вынесите
альтернативу в отдельную строку с `{{^items}}…{{/items}}`.

## 5. Условия

```
Статус: {{#if paid}}оплачено{{else}}ожидает оплаты{{/if}}
```

Для сравнений используйте фильтры:

```
{{#if total | gt: 100000}}Требуется подпись директора{{/if}}
{{#if status | eq: "paid"}}…{{/if}}
{{#if items | length | gte: 10}}Оптовая скидка{{/if}}
{{#unless client.email}}Email не указан{{/unless}}
```

Условия, как и циклы, бывают внутри абзаца, на уровне абзацев и на уровне строк таблицы.
Правила те же, что в разделе 4.

## 6. Фильтры

Фильтр применяется через `|`, аргументы перечисляются после двоеточия через запятую.
Фильтры можно сцеплять:

```
{{ client.name | trim | upper }}
{{ price | number: 2, " ", "," }}
{{ comment | default: "—" | truncate: 100 }}
```

Аргументом может быть и переменная: `{{ nickname | default: fullName }}`.

### Встроенные фильтры

**Строки**

| Фильтр | Пример | Результат |
| --- | --- | --- |
| `upper`, `lower` | `{{ "Кофе" \| upper }}` | `КОФЕ` |
| `capitalize` | `{{ "иван" \| capitalize }}` | `Иван` |
| `trim` | | обрезает пробелы по краям |
| `replace: from, to` | `{{ phone \| replace: "-", "" }}` | заменяет все вхождения |
| `truncate: len, suffix` | `{{ text \| truncate: 20 }}` | обрезка до `len` символов вместе с `…` |
| `prepend: s`, `append: s` | `{{ code \| prepend: "№ " }}` | только для непустых значений |
| `default: x` | `{{ phone \| default: "—" }}` | для `nil`, отсутствующего, `""`, `[]` |

**Числа и даты**

| Фильтр | Пример | Результат |
| --- | --- | --- |
| `number: decimals, thousands, decimal` | `{{ 1234567.891 \| number: 2 }}` | `1 234 567,89` |
| `fixed: decimals` | `{{ 3.14159 \| fixed: 2 }}` | `3.14` |
| `round: decimals` | `{{ 2.5 \| round }}` | `3` |
| `currency: code, locale, decimals` | `{{ 25 \| currency: "EUR", "de-DE" }}` | `25,00 €` |
| `percent: decimals` | `{{ 0.256 \| percent: 1 }}` | `25.6%` |
| `date: format` | `{{ d \| date: "DD.MM.YYYY HH:mm" }}` | `17.05.2024 10:00` |

Значения `coffee.Decimal` фильтры `number`, `fixed`, `round` и `currency` округляют точно (половина —
от нуля), без перехода через `float64`. Для денег используйте `Decimal`.

`currency` знает локали en, de, de-CH, ru, uk, be, kk, fr, es, it, pl, cs, sk, sv, fi, nb, pt,
pt-BR, nl, tr, ja, zh и ko; неизвестная локаль заменяется на `en-US`. Если нужно полноценное ICU-
форматирование, объявите свой фильтр с именем `currency`.

Токены `date`: `YYYY YY MM M DD D HH H mm m ss s`, текст в квадратных скобках выводится как есть:
`{{ d | date: "[Москва,] DD.MM.YYYY" }}`. Фильтр принимает даты, ISO-строки и метки времени в
миллисекундах. О часовых поясах — в разделе 10.

**Коллекции**

| Фильтр | Пример |
| --- | --- |
| `join: sep` | `{{ tags \| join: ", " }}` |
| `length`, `first`, `last`, `reverse` | `{{ items \| length }}` |
| `sort: key, dir` | `{{#each items \| sort: "price", "desc"}}` |
| `where: key, value` | `{{#each items \| where: "status", "paid"}}`; без `value` — по истинности поля |
| `slice: start, end` | `{{#each items \| slice: 0, 5}}` — первые пять |
| `json: indent` | `{{ obj \| json: 2 }}` |

**Сравнения и логика** (для условий)

`eq`, `ne` (`1` равно `"1"`), `gt`, `gte`, `lt`, `lte`, `not`, `empty`, `and`, `or`, `contains`,
а также `yesno: да, нет` — `{{ paid | yesno: "Оплачено", "Не оплачено" }}`.

### Свои фильтры

Фильтр — функция `coffee.Filter`:

```go
type Filter func(value any, args ...any) (any, error)
```

```go
templater := coffee.New(coffee.Options{
	Filters: map[string]coffee.Filter{
		// {{ total | money: "USD" }}
		"money": func(value any, args ...any) (any, error) {
			amount, ok := value.(float64)
			if !ok {
				return nil, fmt.Errorf("money: %v — не число", value)
			}
			currency := "RUB"
			if len(args) > 0 {
				currency = fmt.Sprint(args[0])
			}
			return fmt.Sprintf("%.2f %s", amount, currency), nil
		},
		// {{ count }} {{ count | plural: "товар", "товара", "товаров" }}
		"plural": func(value any, args ...any) (any, error) {
			n, _ := value.(float64)
			m10, m100 := int(n)%10, int(n)%100
			switch {
			case m10 == 1 && m100 != 11:
				return args[0], nil
			case m10 >= 2 && m10 <= 4 && (m100 < 10 || m100 >= 20):
				return args[1], nil
			}
			return args[2], nil
		},
	},
})
```

Какие типы приходят в фильтр:

| В шаблоне | В Go |
| --- | --- |
| строка | `string` |
| число | `float64` |
| `true` / `false` | `bool` |
| `null`, отсутствующее значение | `nil` |
| объект | `map[string]any` |
| массив | `[]any` |
| дата | `coffee.Date` (метод `Time()` разбирает её в `time.Time`) |
| точное десятичное | `coffee.Decimal` |
| бинарные данные | `[]byte` |

- Фильтр может вернуть любое значение, которое допустимо в данных (раздел 10): строку, число,
  структуру, срез, `coffee.Date`… Поэтому свои фильтры работают и в условиях, и в циклах:
  `{{#each items | onlyActive}}`.
- Свой фильтр с тем же именем, что у встроенного, заменяет встроенный.
- Неизвестный фильтр в шаблоне — ошибка уже при `Compile` (`ErrUnknownFilter`).
- Возвращённая ошибка или **паника** внутри фильтра становится ошибкой `ErrFilterFailed`, текст лежит
  в `Details["hostMessage"]`. Паника перехватывается, движок продолжает работать.
- Фильтры вызываются синхронно, в горутине, которая вызвала `Render`. Если один `Template` рендерится
  параллельно, фильтр тоже вызывается параллельно: общее состояние в нём защищайте мьютексом.
- Сколько раз вызываются фильтры за один рендер, ограничивает `Limits.MaxHostCalls`.

## 7. Картинки

В шаблоне — тег с `%`: `{{%logo}}`. В данных — `coffee.Image`:

```go
logo, _ := os.ReadFile("logo.png")

doc, err := templater.Render(ctx, template, map[string]any{
	"logo": coffee.Image{
		Data:      logo,      // байты файла
		Width:     120,       // пиксели при 96 dpi, необязательно
		Height:    60,        // необязательно
		Extension: "png",     // необязательно, определяется по содержимому
		Alt:       "Логотип", // альтернативный текст
	},
})
```

- Формат определяется автоматически для PNG, JPEG, GIF, BMP и SVG. Для `tif`, `webp`, `emf`, `wmf`,
  `ico` укажите `Extension`.
- Размер: если не задан — натуральный размер картинки; если задана только ширина или только
  высота, вторая сторона считается по пропорциям.
- `nil`, `false` или `""` вместо картинки — тег удаляется. Удобно поле `*coffee.Image`: `nil` убирает
  картинку. В режиме `Strict` отсутствующее значение — ошибка.
- Байты уходят в ядро бинарным блобом, без base64. Одна и та же картинка (те же байты и расширение),
  использованная много раз, например в цикле, хранится в документе один раз.
- Вместо `coffee.Image` подойдёт любая структура или map с такими же полями (`data`, `width`, …).

**Word.** Картинка вставляется прямо на место тега, в строку текста. Тег можно поставить
в абзац, ячейку таблицы, колонтитул или внутрь цикла.

**PowerPoint.** Поставьте `{{%logo}}` в отдельное текстовое поле или плейсхолдер. Поле целиком
заменяется картинкой, вписанной в его границы (с сохранением пропорций, по центру).

**Excel.** Пока не поддерживается: тег-картинка в книге даёт ошибку `ErrUnsupported`.

## 8. Экранирование

**Значения из данных** всегда экранируются: `<`, `>`, `&` и кавычки в данных не могут сломать
документ или внедрить разметку. Недопустимые в XML управляющие символы удаляются.

**Разделители в тексте.** Чтобы вывести `{{` буквально, поставьте перед ним символ экранирования
(по умолчанию `\`):

| В шаблоне | В результате |
| --- | --- |
| `\{{name}}` | `{{name}}` |
| `\\{{name}}` | `\` и значение `name` |
| `C:\temp\{{file}}` | `C:\temp` и значение `file`: обратный слеш не перед разделителем не трогается |

Символ экранирования настраивается: `EscapeChar: "!"`, отключается через `NoEscape: true`.

## 9. Особенности форматов

### Word (.docx)

- Обрабатываются основной текст, верхние и нижние колонтитулы, сноски и концевые сноски.
- Word часто режет текст на фрагменты (run'ы) из-за проверки орфографии, истории правок и смены
  форматирования: `{{na` + `me}}`. Такие теги склеиваются автоматически. Значение получает
  форматирование того фрагмента, в котором тег **начинается**.
- Тег не может переходить из одного абзаца в другой: это ошибка `unclosed_tag`.

### Excel (.xlsx)

- Обрабатываются все листы. Строки из общей таблицы строк (`sharedStrings`), содержащие теги,
  переносятся в ячейки, остальные остаются общими.
- **Типы ячеек.** Если ячейка состоит ровно из одного тега, а значение — число, `Decimal` или `bool`,
  ячейка становится числовой или логической, и формулы с ней работают. Если вокруг тега есть текст
  (`Итого: {{sum}}`), ячейка остаётся строкой.
- **Сдвиг строк.** Циклы по строкам перенумеровывают строки ниже, как при вставке и удалении строк в
  Excel. За сдвинутыми строками следуют:
  - формулы на всех листах: `=SUM(D3:D3)` в строке итогов становится `=SUM(D3:D12)`, а формулы внутри
    повторяемой строки (`=B3*C3`) ссылаются на свою копию;
  - именованные диапазоны, области печати, «умные таблицы», автофильтры и сортировка;
  - объединённые ячейки (внутри повторяемой строки дублируются), условное форматирование, проверка
    данных, гиперссылки, комментарии, разрывы страниц, привязки рисунков, ряды диаграмм, источники
    сводных таблиц.
- **Пустой цикл** удаляет свои строки так, как это сделал бы Excel: ссылка на удалённую строку
  становится `#REF!`, диапазон сужается. Если итог считается по циклу, который может оказаться
  пустым, оберните формулу в `IFERROR(…, 0)`.
- Shared-формулы, задевающие повторяемые строки, записываются как обычные формулы.
- После рендера удаляется `calcChain.xml` и включается пересчёт формул при открытии.

Подробный список — в [DOCS.md ядра](https://github.com/vitJR1/coffee-templater-engine/blob/main/DOCS.md#excel-specifics).

### PowerPoint (.pptx)

- Обрабатываются все слайды по порядку и заметки докладчика.
- Циклы по абзацам работают внутри одного текстового поля, циклы по строкам — в таблицах.
- Перенос строки в значении становится `<a:br>` с сохранением форматирования.
- Повтор целых слайдов пока не поддерживается.

## 10. Данные: как Go-значения попадают в шаблон

Данные можно передать любым значением: `map[string]any`, структурой, срезом. Они преобразуются по
правилам `encoding/json`, с несколькими дополнениями для дат, денег и бинарных данных.

### Как в encoding/json

- Экспортируемые поля структур; имя берётся из тега `json`, опции `omitempty`, `omitzero` и `-`
  учитываются.
- Поля встроенных (embedded) структур поднимаются наверх; при совпадении имён побеждает менее
  вложенное поле, затем поле с тегом.
- Указатели и интерфейсы разыменовываются, `nil` становится `null`.
- Ключи map — строки, целые числа или типы с `MarshalText`. **Ключи сортируются**, поэтому одни и те
  же данные всегда дают один и тот же документ.
- Типы с `MarshalJSON` (`json.Marshaler`) вставляются как вернул метод, типы с `MarshalText` — строкой.
- `float64` форматируется как в JSON (и в JavaScript): `10.5`, `1e+21`. `NaN` и `±Inf` дают `null`.
- Функции, каналы и комплексные числа превращаются в `null`.
- Циклические ссылки дают ошибку, а не зависание. Ядро принимает до 128 уровней вложенности.

```go
type Client struct {
	Name  string `json:"name"`
	Email string `json:"email,omitempty"`
}

type Invoice struct {
	Number int     `json:"number"`
	Client Client  `json:"client"`
	Items  []Item  `json:"items"`
	Paid   bool    `json:"paid"`
	Secret string  `json:"-"` // в шаблон не попадёт
}

doc, err := tpl.Render(ctx, invoice) // {{number}}, {{client.name}}, {{#items}}…
```

### Дополнения

| Go | В шаблоне |
| --- | --- |
| `time.Time` | дата: момент времени в UTC, либо местное время в `Options.TimeZone` |
| `coffee.Date("2024-05-17")` | «наивная» дата без часового пояса, выводится как записана |
| `coffee.Decimal("1234.50")` | точное десятичное число |
| `*big.Float`, `*big.Rat` | точное десятичное (`Rat` с бесконечной дробью — как `float64`) |
| `*big.Int`, `json.Number` | число без потери точности: `12345678901234567890` выводится целиком |
| `[]byte` | бинарные данные (картинки), передаются блобом, не base64 |
| `json.RawMessage` | вставляется как есть |
| `coffee.Image` | картинка для `{{%tag}}` |

Объекты, похожие на служебные значения ядра (`map[string]any{"$date": "…"}` — ровно один ключ из
`$date`, `$decimal`, `$blob`, `$base64`, `$literal`), передаются буквально: случайно подделать дату или
блоб данными пользователя нельзя.

### Даты и часовые пояса

У ядра нет часов и базы часовых поясов, поэтому дату надо передать в нужном виде.

- **`time.Time`** — момент времени. По умолчанию он уходит в UTC (`2024-05-17T07:00:00.000Z`), и
  результат одинаков на любом сервере. `{{ d | date: "DD.MM.YYYY" }}` покажет дату по UTC.
- Чтобы видеть местное время, задайте `Options.TimeZone`: тогда `time.Time` переводится в этот пояс и
  уходит как местное время без зоны.

  ```go
  moscow, _ := time.LoadLocation("Europe/Moscow")
  templater := coffee.New(coffee.Options{TimeZone: moscow})
  ```

- **`coffee.Date`** — дата как в Excel, без пояса: `Date("2024-05-17")`, `Date("2024-05-17T10:00:00")`.
  Выводится как записана. Хелперы: `coffee.DateOf(t)` (только дата `t` в её поясе) и
  `coffee.DateTimeOf(t)` (местное время `t`).
- Дата со смещением (`Date("2024-05-17T10:00:00+03:00")`) приводится к UTC.
- Формат дат, выведенных без фильтра, задаёт `Options.DateFormat` (по умолчанию ISO).

### Деньги

`float64` неточен: `0.1 + 0.2` не равно `0.3`. Для сумм передавайте `coffee.Decimal`, тогда
`number`, `fixed`, `round` и `currency` округляют точно:

```go
// github.com/shopspring/decimal
"price": coffee.Decimal(price.String())

// или прямо в структуре
type Item struct {
	Name  string         `json:"name"`
	Price coffee.Decimal `json:"price"`
}
```

## 11. Настройки

```go
coffee.New(coffee.Options{
	// Разделители тегов; по умолчанию {{ }}
	Delimiters: coffee.Delimiters{Start: "${", End: "}"},

	// Символ экранирования разделителей; по умолчанию `\`. NoEscape: true — отключить
	EscapeChar: `\`,

	// Служебные символы и ключевые слова; пустые поля — по умолчанию
	Syntax: coffee.Syntax{
		Section:  "#",      // {{#items}}
		Inverted: "^",      // {{^items}}
		Close:    "/",      // {{/items}}
		Image:    "%",      // {{%logo}}
		Else:     "else",   // {{else}}
		If:       "if",     // {{#if x}}
		Unless:   "unless", // {{#unless x}}
		Each:     "each",   // {{#each x}}
	},

	// Свои фильтры (добавляются к встроенным), раздел 6
	Filters: map[string]coffee.Filter{},

	// Отсутствующее значение — ошибка ErrMissingValue
	Strict: false,

	// Что выводить для nil и отсутствующих значений
	NullValue: coffee.NullValue{Mode: coffee.NullEmpty},

	// Как превращать в текст нестроковые значения; по умолчанию — правила из раздела 3
	Stringify: func(v any) (string, error) { return fmt.Sprint(v), nil },

	// Формат дат без фильтра, например "DD.MM.YYYY"; по умолчанию ISO
	DateFormat: "",

	// Часовой пояс для time.Time; по умолчанию UTC
	TimeZone: nil,

	// true — не превращать \n в перенос строки, \t в табуляцию
	NoLinebreaks: false,

	// Защита от недоверенных файлов: 0 — значение по умолчанию, coffee.Unlimited — без ограничения
	Limits: coffee.Limits{
		MaxInputBytes:        100 << 20, // размер файла
		MaxEntries:           10_000,    // файлов в ZIP
		MaxUncompressedBytes: 500 << 20, // распакованный размер
		MaxCompressionRatio:  200,       // защита от zip-бомб
		MaxXMLDepth:          256,       // вложенность XML
		MaxOutputBytes:       500 << 20, // размер результата
		MaxLoopIterations:    1_000_000, // итераций циклов за рендер
		MaxHostCalls:         1_000_000, // вызовов своих фильтров, NullValue.Func, Stringify
	},

	// Движок; по умолчанию coffee.DefaultEngine(), раздел 15
	Engine: nil,
})
```

Нулевое значение `Options{}` даёт настройки по умолчанию. Неверные настройки (пустые или одинаковые
разделители, пустой символ синтаксиса) обнаруживаются при первом `Compile` или `Render` как
`ErrInvalidOptions`.

### Отсутствующие значения

| `NullValue` | Что выводится вместо `{{client.phone}}` без значения |
| --- | --- |
| `{}` или `{Mode: coffee.NullEmpty}` | пустая строка |
| `{Mode: coffee.NullText, Text: "—"}` | `—` |
| `{Mode: coffee.NullKeep}` | сам тег `{{client.phone}}` — удобно для черновиков |
| `{Mode: coffee.NullError}` | ошибка `ErrMissingValue`, как `Strict: true` |
| `{Func: f}` | то, что вернёт `f(tag)` |

```go
// подсветка отсутствующих данных
coffee.New(coffee.Options{NullValue: coffee.NullValue{
	Func: func(tag coffee.TagInfo) (any, error) {
		return "[НЕТ ДАННЫХ: " + tag.Expression + "]", nil
	},
}})
```

`TagInfo` содержит `Raw` (тег целиком), `Expression` (выражение внутри) и `Part` (часть документа,
например `word/document.xml`).

### Примеры разделителей

| Настройка | Теги в документе |
| --- | --- |
| `Delimiters{"{{", "}}"}` | `{{name}}`, `{{#items}}` |
| `Delimiters{"${", "}"}` | `${name}`, `${#items}` |
| `Delimiters{"[[", "]]"}` | `[[name]]` |
| `Delimiters{"<<", ">>"}` | `<<name>>` — угловые скобки в XML обрабатываются корректно |
| `Delimiters{"{", "}"}` | `{name}` — как в docxtemplater |

### Русскоязычный синтаксис

```go
coffee.New(coffee.Options{Syntax: coffee.Syntax{If: "если", Else: "иначе", Each: "для"}})
```

```
{{#если оплачено}}Оплачено{{иначе}}Ожидает оплаты{{/если}}
```

## 12. Инспекция шаблона

`Inspect` разбирает шаблон и рассказывает, какие данные ему нужны, без рендера:

```go
info, err := templater.Inspect(ctx, template)
// или tpl.Inspect(ctx) у скомпилированного шаблона (результат кэшируется)
```

```go
info.Format    // coffee.Docx

info.Variables // плоский список путей
// [number client.name items[].name items[].price items[].qty paid notes logo total company]

info.Schema    // пример данных нужной формы
// map[client:map[name:] items:[map[name: price: qty:]] logo:<nil> number: paid:true]

info.Tags      // дерево тегов: []coffee.Tag
info.Parts     // то же дерево по частям документа (тело, колонтитулы, слайды)
```

Как читать `Schema`: строки — переменные, массивы — циклы, `true` — условия, `nil` — картинки.

Узел дерева `coffee.Tag`:

| Поле | Значение |
| --- | --- |
| `Type` | `coffee.TagVariable`, `coffee.TagImage` или `coffee.TagSection` |
| `Path` | путь данных: `client.name` |
| `Expression` | выражение целиком: `price \| number: 2` |
| `Raw` | тег в документе: `{{price \| number: 2}}` |
| `Filters` | имена фильтров переменной |
| `Mode` | у секций: `ModeSection`, `ModeInverted`, `ModeIf`, `ModeUnless`, `ModeEach` |
| `Children`, `ElseChildren` | вложенные теги секции и её ветки `else` |

Применения:
- построить форму по загруженному пользователем шаблону;
- проверить, что бэкенд передаёт все нужные поля (например, сгенерировать по `Schema` JSON Schema);
- показать пользователю список доступных переменных.

`{{#x}}` считается циклом, если внутри секции используются данные, и условием, если нет.
`{{#each}}` — всегда цикл.

## 13. Ошибки

Ошибки ядра имеют тип `*coffee.Error`:

```go
type Error struct {
	Problem            // первая проблема: Code, Message, Part, Tag, Location, Details
	Problems []Problem // все проблемы
}
```

| Поле `Problem` | Пример |
| --- | --- |
| `Code` | `coffee.ErrUnclosedSection` (`"unclosed_section"`) |
| `Message` | `Section is never closed` |
| `Tag` | `{{#items}}` |
| `Part` | `word/document.xml` |
| `Location` | где именно: `Paragraph`, `Cell` (`"B12"`), `Slide`, `Row`, если известно |
| `Details` | дополнительно: `hostMessage` у `filter_failed`, `limit` у `limit_exceeded` |

Коды ошибок (`coffee.ErrorCode`) сами реализуют `error`, поэтому работает `errors.Is`. Он проверяет
**все** проблемы, а не только первую:

```go
tpl, err := templater.Compile(ctx, file)
if errors.Is(err, coffee.ErrUnknownFilter) {
	// в шаблоне есть неизвестный фильтр
}

var e *coffee.Error
if errors.As(err, &e) {
	for _, p := range e.Problems {
		log.Printf("%s: %s (%s в %s)", p.Code, p.Message, p.Tag, p.Part)
	}
}
```

Текст ошибки: `coffee: Section is never closed (tag {{#items}} in word/document.xml) (+1 more)`.

**Ошибки шаблона**

| Код | Константа | Причина |
| --- | --- | --- |
| `unclosed_tag` | `ErrUnclosedTag` | нет закрывающего разделителя, или тег разорван между абзацами |
| `unopened_tag` | `ErrUnopenedTag` | закрывающий разделитель без открывающего |
| `unclosed_section` | `ErrUnclosedSection` | `{{#x}}` без `{{/x}}` |
| `unmatched_close` | `ErrUnmatchedClose` | лишний `{{/x}}`, несовпадающее имя, `{{else}}` вне секции |
| `invalid_expression` | `ErrInvalidExpression` | синтаксическая ошибка в выражении, пустой тег |
| `unknown_filter` | `ErrUnknownFilter` | фильтр не существует (проверяется при компиляции) |
| `filter_failed` | `ErrFilterFailed` | свой фильтр вернул ошибку или запаниковал |
| `missing_value` | `ErrMissingValue` | нет значения в режиме `Strict` |
| `invalid_section` | `ErrInvalidSection` | теги секции в несовместимых местах, пересечение секций, неверный `else` |
| `invalid_image` | `ErrInvalidImage` | значение картинки — не картинка, или тег не в фигуре (pptx) |
| `unsupported` | `ErrUnsupported` | не поддерживается в этом формате (картинки в Excel) |

**Ошибки уровня ядра**

| Код | Константа | Причина |
| --- | --- | --- |
| `invalid_request` | `ErrInvalidRequest` | неверный запрос, например неверная дата в `coffee.Date` |
| `invalid_options` | `ErrInvalidOptions` | неверные настройки |
| `invalid_document` | `ErrInvalidDocument` | файл не ZIP или не Office-документ, битый XML, опасные пути в ZIP |
| `unsupported_format` | `ErrUnsupportedFormat` | ZIP, но не docx/xlsx/pptx |
| `invalid_model` | `ErrInvalidModel` | модель для `Build` не соответствует схеме (или pptx без base) |
| `unknown_template` | `ErrUnknownTemplate` | внутренний хэндл шаблона не найден |
| `limit_exceeded` | `ErrLimitExceeded` | превышен лимит, в `Details["limit"]` — какой именно |
| `host_error` | `ErrHostError` | ошибка в `NullValue.Func` или `Stringify` |
| `internal` | `ErrInternal` | сбой внутри ядра — пожалуйста, создайте issue |

**Все ошибки сразу.** Если в шаблоне несколько ошибочных тегов, `Compile` сообщает обо всех. Структурные
ошибки (незакрытые секции) в части документа проверяются после того, как исправлены ошибки в самих
тегах этой части.

Ошибки шаблона обнаруживаются при `Compile`, ошибки данных (`missing_value`, `filter_failed`,
`invalid_image`) — при `Render`.

**Не ошибки ядра.** Кроме `*coffee.Error`, методы возвращают:
- `ctx.Err()` (`context.Canceled`, `context.DeadlineExceeded`), если контекст отменён;
- ошибку преобразования данных, например при циклической ссылке или ошибке в `MarshalJSON`;
- ошибку закрытого шаблона, если `Render` вызван после `Close`.

## 14. Модель документа: Parse → структуры → Build

Помимо шаблонов, библиотека умеет разбирать документ в Go-структуры, которые удобно менять в коде,
хранить и сериализовать в JSON, а затем собирать документ обратно.

```go
original, _ := os.ReadFile("contract.docx")

doc, err := coffee.Parse(ctx, original) // *coffee.Document
// … меняем doc …
updated, err := coffee.Build(ctx, doc, original)
```

`coffee.Document` — одна структура для всех форматов: в зависимости от `Format` заполнено `Parts`
(docx), `Sheets` (xlsx) или `Slides` (pptx). Структуры сериализуются в тот же JSON, что и модель в
JavaScript-библиотеке, так что модель можно, например, отдать на фронтенд через `json.Marshal` и
принять обратно.

### Как сохраняется форматирование

Каждый абзац, фрагмент текста, ячейка и фигура хранит исходные XML-свойства в поле `Props`.
Удобные поля (`Bold`, `Size`, `Color`, `Align`, …) читаются из них. При сборке поле записывается
в XML, **только если вы его изменили**, поэтому всё, что модель не описывает (интервалы, отступы,
границы, языки, эффекты), переживает цикл `Parse → Build` без потерь.

Необязательные поля-флаги — указатели: `nil` значит «не задано». Присвоить `nil` значит снять
свойство: `run.Bold = nil` уберёт жирность. Для установки удобен `coffee.Ptr`:

```go
run.Bold = coffee.Ptr(true)
run.Size = coffee.Ptr(14.0)
run.Underline = &coffee.Underline{On: true}       // одинарное подчёркивание
run.Underline = &coffee.Underline{Type: "double"} // или тип подчёркивания
```

То, что модель не покрывает (изображения, поля, закладки, элементы управления содержимым,
отслеживаемые изменения), хранится как элемент `Type: "raw"` с XML и возвращается на место как есть.

Объединения (абзац или таблица, фрагмент текста или разрыв, текстовая фигура или картинка) —
одна структура с полем `Type`; заполнены поля, относящиеся к этому типу.

### Word

```go
coffee.Document{
	Format: coffee.Docx,
	Parts: []coffee.DocxPart{{
		Path:         "word/document.xml",
		Kind:         "body",          // "body" | "header" | "footer"
		SectionProps: "<w:sectPr>…",   // размер страницы, поля, ссылки на колонтитулы
		Blocks: []coffee.DocxBlock{
			{
				Type:  "paragraph",
				Style: "Heading1",                       // id стиля абзаца
				Align: "center",                         // left | center | right | justify
				List:  &coffee.ListRef{ID: 1, Level: 0}, // нумерованный/маркированный список
				Children: []coffee.DocxInline{
					{
						Type: "run",

							Underline: &coffee.Underline{On: true}, Strike: coffee.Ptr(false),
							Color: "FF0000", Highlight: "yellow",
							Size:  coffee.Ptr(14.0), // пункты
							Font:  "Arial", VertAlign: "superscript",
							Style: "Strong",          // id стиля символов
						},
					},
					{Type: "hyperlink", URL: "https://example.com",
						Children: []coffee.DocxInline{{Type: "run", Text: "ссылка"}}},
					{Type: "hyperlink", Anchor: "bookmark1"},

				},
			},
			{
				Type: "table",
				Rows: []coffee.DocxTableRow{{Cells: []coffee.DocxTableCell{
					{Blocks: []coffee.DocxBlock{ /* абзацы, вложенные таблицы */ }, ColSpan: 2},

```

- `\n` в тексте — перенос строки, `\t` — табуляция, `U+2011` — неразрывный дефис, `U+00AD` — мягкий
  перенос.
- Соседние фрагменты с одинаковым форматированием при разборе склеиваются.
- `Build` без base создаёт новый документ со стилями `Normal`, `Title`, `Heading1`–`Heading3`,
  `ListParagraph`, `TableGrid` (используются только части с `Kind: "body"`).

### Excel

```go
coffee.Document{
	Format: coffee.Xlsx,
	Sheets: []coffee.XlsxSheet{{
		Name:   "Отчёт",
		Path:   "xl/worksheets/sheet1.xml", // пусто — будет создан новый лист
		Merges: []string{"A1:D1"},
		Rows: []coffee.XlsxRow{{
```

- Shared-формулы разворачиваются по ячейкам. `Formula` — без ведущего `=`.
- Форматированный текст внутри ячейки (`RichText`) сохраняется, пока не изменён текст.
- `Ref` можно не указывать: ячейка встанет в колонку после предыдущей.
- Листы можно переименовывать, переставлять, добавлять и удалять: лист, отсутствующий в модели,
  удаляется. Ширины колонок, закрепления, фильтры, условное форматирование существующих листов
  берутся из base.

## 15. Движок: пул, параллельность, отмена

Экземпляр WebAssembly однопоточный, поэтому библиотека держит **пул экземпляров** (`*coffee.Engine`).
Каждая операция берёт свободный экземпляр, выполняется на нём и возвращает его в пул. Если все
экземпляры заняты, операция ждёт (или завершается по отмене `ctx`).

По умолчанию используется `coffee.DefaultEngine()`: он создаётся при первом вызове, экземпляров не
больше `runtime.GOMAXPROCS(0)`. Свой движок нужен, чтобы изменить настройки:

```go
engine, err := coffee.NewEngine(ctx, coffee.EngineConfig{
	MaxInstances: 4,                   // сколько операций выполняется параллельно
	CacheDir:     "/var/cache/coffee", // кэш скомпилированного машинного кода на диске
	Interpreter:  false,               // true — интерпретатор wazero вместо компилятора
})
if err != nil {
	return err
}
defer engine.Close(ctx)

templater := coffee.New(coffee.Options{Engine: engine})
doc, err := engine.Parse(ctx, file) // Parse, Build, ExtractText, DetectFormat, Info
```

### Шаблоны и экземпляры

- Скомпилированный шаблон живёт внутри экземпляра. `Template` хранит копию исходного файла и
  компилируется **лениво на каждом экземпляре**, на котором его рендерят, — при первом рендере там.
  Первый рендер на новом экземпляре поэтому чуть медленнее.
- `tpl.Close()` освобождает шаблон во всех экземплярах: память освобождается перед следующей
  операцией каждого экземпляра. Повторный `Close` ничего не делает. Если забыть `Close`, шаблон
  освободит финализатор при сборке мусора, но полагаться на это не стоит.
- `Template.Format()` и `Template.Parts()` возвращают формат и части документа с тегами.

### Отмена и тайм-ауты

Все методы принимают `context.Context`. Отмена контекста или истечение тайм-аута **прерывает ядро**
посреди работы, даже долгий рендер:

```go
ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
defer cancel()
doc, err := tpl.Render(ctx, data)
if errors.Is(err, context.DeadlineExceeded) { … }
```

Прерванный экземпляр выбрасывается из пула (его состояние после прерывания не определено), вместо него
создаётся новый. Шаблоны перекомпилируются на нём автоматически.

Если ядро упадёт (trap внутри WebAssembly), операция вернёт `ErrInternal`, экземпляр тоже будет
заменён.

### Производительность

- Создание движка компилирует WebAssembly в машинный код: около 0,3 с на процесс. Это происходит один
  раз; с `CacheDir` следующие запуски процесса берут готовый код с диска.
- У каждого экземпляра своя память, она растёт с размером обработанных документов и не уменьшается.
  `MaxInstances` ограничивает и параллельность, и общий расход памяти.
- Рендер небольшого счёта .docx — единицы миллисекунд; бенчмарки: `go test -bench . -run x`.
- Для массовой генерации компилируйте шаблон один раз и рендерьте из нескольких горутин: пул
  распределит работу по экземплярам.

### Повторный вход

Фильтр, `NullValue.Func` или `Stringify` выполняются, пока экземпляр занят. Из них можно вызывать
библиотеку (операция возьмёт **другой** экземпляр), но если все экземпляры пула заняты, такой вызов
будет ждать вечно. Не рендерьте из фильтров; если очень нужно — используйте отдельный `Engine`.

### Версия ядра

```go
coffee.EngineVersion // "0.1.2" — версия встроенного ядра
coffee.EngineSHA256  // sha256 встроенного coffee_core.wasm
coffee.ModelVersion  // версия модели документа

info, _ := engine.Info(ctx) // CoreVersion, ABIVersion, ModelVersion, Formats, Features
```

### HTTP: генерация документа по запросу

```go
var invoiceTpl *coffee.Template

func main() {
	ctx := context.Background()
	file, err := os.ReadFile("templates/invoice.docx")
	if err != nil {
		log.Fatal(err)
	}
	invoiceTpl, err = coffee.New(coffee.Options{}).Compile(ctx, file)
	if err != nil {
		log.Fatal(err) // ошибка в шаблоне — при старте, а не при первом запросе
	}

	http.HandleFunc("GET /invoices/{id}", func(w http.ResponseWriter, r *http.Request) {
		inv, err := db.FindInvoice(r.Context(), r.PathValue("id"))
		if err != nil {
			http.Error(w, err.Error(), http.StatusNotFound)
			return
		}
		ctx, cancel := context.WithTimeout(r.Context(), 10*time.Second)
		defer cancel()
		doc, err := invoiceTpl.Render(ctx, inv) // клиент ушёл — рендер прерывается
		var e *coffee.Error
		switch {
		case errors.As(err, &e):
			w.WriteHeader(http.StatusUnprocessableEntity)
			json.NewEncoder(w).Encode(map[string]any{"code": e.Code, "tag": e.Tag})
			return
		case err != nil:
			http.Error(w, err.Error(), http.StatusInternalServerError)
			return
		}
		w.Header().Set("Content-Type", "application/vnd.openxmlformats-officedocument.wordprocessingml.document")
		w.Header().Set("Content-Disposition", fmt.Sprintf(`attachment; filename="invoice-%d.docx"`, inv.Number))
		w.Write(doc)
	})
	log.Fatal(http.ListenAndServe(":8080", nil))
}
```

### Шаблоны от пользователей

```go
// при загрузке шаблона: проверить и сохранить список переменных
limits := coffee.Limits{MaxInputBytes: 20 << 20, MaxLoopIterations: 100_000}
templater := coffee.New(coffee.Options{Strict: true, Limits: limits})

info, err := templater.Inspect(ctx, uploaded)
if err != nil {
	return err // все ошибки шаблона — пользователю
}

```

`Strict: true` при рендере гарантирует, что пропущенное поле не превратится в незаметную пустоту
в документе. Лимиты защищают от zip-бомб и шаблонов с огромными циклами, а тайм-аут контекста — от
долгого рендера.

### Отчёт Excel с итогами

Шаблон:

| | A | B | C | D | E |
| --- | --- | --- | --- | --- | --- |
| 1 | Отчёт за `{{period}}` | | | | |
| 2 | Товар | Кол-во | Цена | Сумма | |
| 3 | `{{#rows}}{{name}}` | `{{qty}}` | `{{price}}` | `=B3*C3` | `{{/rows}}` |
| 4 | Итого | | | `=SUM(D3:D3)` | |

После рендера со ста строками формула итогов станет `=SUM(D3:D102)`, а каждая `=B3*C3`
будет ссылаться на свою строку. Числа (`qty`, `price`) останутся числовыми ячейками.

### Массовая генерация в ZIP

```go
tpl, err := coffee.New(coffee.Options{}).Compile(ctx, templateBytes)
```

## 17. Устройство библиотеки

```
coffee-templater.go (этот модуль)            coffee-templater-engine (отдельный репозиторий)
┌───────────────────────────────┐            ┌──────────────────────────────────────────────┐
```

Код ядра в этот репозиторий не копируется: в `internal/wasm` лежит только готовый `coffee_core.wasm`

### Структура

```

├── values.go            Go → JSON ядра: структуры, даты, Decimal, блобы; JSON ядра → Go
├── engine.go            Engine: wazero, пул экземпляров, ct_alloc/ct_call, импорт ct_host.call
├── frame.go             формат кадров "CTF1"
├── errors.go            Error, Problem, ErrorCode
├── inspect.go           результат Inspect: дерево тегов
├── model.go             модель документа, Parse / Build / ExtractText / DetectFormat / Info

├── testdata/conformance копия conformance-набора ядра
└── scripts/update-engine.sh   обновление ядра
```

### Как проходит вызов

1. Данные преобразуются в JSON ядра (раздел 10). `[]byte` не кодируются в base64, а собираются в
   список бинарных блобов; в JSON на них ссылается `{"$blob": n}`.
2. Запрос упаковывается в кадр (`CTF1` + JSON + блобы).
3. Из пула берётся экземпляр. Если шаблон на нём ещё не скомпилирован, сначала выполняется `compile`.
4. Кадр копируется в память WebAssembly через `ct_alloc`, выполняется `ct_call`.
5. Если шаблону нужны свои фильтры, `NullValue.Func` или `Stringify`, ядро синхронно вызывает
   импорт `ct_host.call`. Обёртка выполняет Go-функцию и возвращает результат кадром. Ошибки и паники
   в пользовательском коде перехватываются и становятся ответом `ok: false`, а не падением ядра.
6. Ответ копируется из памяти WebAssembly и освобождается через `ct_free`. Ошибки превращаются в
   `*coffee.Error`, экземпляр возвращается в пул.

Протокол, ABI и модель описаны в [DOCS.md ядра](https://github.com/vitJR1/coffee-templater-engine/blob/main/DOCS.md).

## 18. Разработка

Все команды не требуют ничего, кроме Go:

```bash
go test ./...            # модульные тесты, примеры и conformance-набор
go test -race ./...      # то же с детектором гонок
go vet ./...
go test -bench . -run x  # бенчмарки: запуск движка, параллельный рендер
```

### Conformance-набор

`testdata/conformance` — копия языконезависимого набора кейсов из репозитория ядра: шаблоны,
данные, ожидаемые ошибки, тексты и **sha256 отрендеренных документов**. `TestConformance` прогоняет
каждый кейс через публичный Go API (данные превращаются в Go-значения так, как это сделало бы
приложение: `json.Number`, `coffee.Decimal`, `coffee.Date`, `[]byte`). Ядро детерминировано, поэтому
хэши должны совпасть с теми, что получают раннеры ядра на Rust и JavaScript. Расхождение хэша значит,
что обёртка передала ядру что-то не так.

`TestModelLossless` проверяет, что Go-структуры модели несут всё, что отдаёт ядро: JSON после
`Parse` и обратной сериализации совпадает с ответом ядра.

### Откуда берётся ядро

Версия ядра закреплена в `internal/wasm/wasm.go` (`Version`, `SHA256`), а `TestEmbeddedEngine`
проверяет, что встроенный файл совпадает с закреплённым хэшем.

```bash
# встроить релиз ядра: скачать coffee_core.wasm и coffee_core.wasm.sha256 из GitHub Release v0.1.3,
# сверить контрольную сумму, обновить Version и SHA256
scripts/update-engine.sh 0.1.3

# локальная сборка ядра — для разработки ядра
(cd ../coffee-templater-engine && make wasm)
scripts/update-engine.sh --local ../coffee-templater-engine/dist/coffee_core.wasm
```

Если рядом лежит checkout ядра (`../coffee-templater-engine` или `ENGINE_DIR`), скрипт заодно копирует
conformance-набор. Убедитесь, что checkout соответствует встраиваемой версии.

**Перед релизом** встройте релиз ядра (а не `--local`): в репозиторий должен попасть бинарник с
известным происхождением.

### CI

`.github/workflows/ci.yml` на каждый push в `main` и PR запускает `go vet`, `go test -race` на
Linux, macOS и Windows с Go 1.23 и последней стабильной версией, и проверяет `gofmt`.

### Релиз

Go-модули публикуются тегом:

```bash
git tag v0.1.2
git push origin v0.1.2
```

После этого версия доступна через `go get github.com/vitJR1/coffee-templater.go@v0.1.2`, а документация
появляется на pkg.go.dev. Номер версии модуля удобно держать равным версии встроенного ядра.

### Зависимости

Единственная зависимость — `github.com/tetratelabs/wazero`, закреплённая на v1.10.1: это последняя
версия, поддерживающая Go 1.23 (v1.11 и новее требуют Go 1.24+). При повышении минимальной версии Go
можно обновить и wazero.

## 19. Ограничения и планы

- Картинки в шаблонах Excel.
- Повтор целых слайдов PowerPoint.
- Отслеживаемые изменения и комментарии Word сохраняются как raw XML и не моделируются.
- Данные передаются целиком: нет ленивых значений и потоков, свои фильтры синхронные.
- Числа в фильтрах приходят как `float64`: большие целые и точные дроби теряют точность внутри
  фильтра. Передавайте такие значения как `coffee.Decimal`, они придут в фильтр как есть.
- Модель документа не типобезопасна для объединений: абзац и таблица — одна структура `DocxBlock`
  с полем `Type`.
- Обёртка для Python поверх того же ядра — в планах; спецификация обёрток — в
  [репозитории ядра](https://github.com/vitJR1/coffee-templater-engine/blob/main/docs/core-spec.md).
